## 二、VB短视频审核 10.1（当前推荐）

### 判定链（每个样本）

```
① 得分 ≤ 74（面板可调）              → 错误（低分，直接判错，不送检测）
② 图片检测失败（下载/解码失败）        → 错误
③ 第5列图 vs 第6列图 相似度 < 0.40    → 错误
④ 检出手机 / 检出屏幕（置信度 ≥ 0.55）  → 错误
⑤ 无人（人物置信度 < 0.35 且人脸未命中）→ 错误
以上均不命中                          → 正确
```

> 10.1 只是把「判定所需的两次请求」合并成一次，**判定规则与结果完全一致**（已验证逐场景等价）。

### 一页一轮流程

```
等表格稳定 → 预热图片（滚动触发懒加载）→ 取本页所有行
   ↓ 低分行（≤74）直接判错，不送后端；其余行分批送检（每批 6 条）—— 一律【先相似度 → 再对剩余行做 YOLO】
       · 有合并接口：POST /review_batch（一次请求；相似度不过阈值直接返回、不跑 YOLO；第5列图只下一次）
       · 旧后端没有该接口：先 /compare 全部 → 相似度不达标的直接判错、不送检测 → 只对剩余行 /detect_batch_detail
   ↓ 判定：错误 / 正确（面板日志 + F12 console.table 明细）
勾选【错误】行（逐行）→ 「批量错误」+确认 → 等错误行从列表消失
   ↓
勾选【正确】行：先确认错误行已全部消失 → 点【表头全选】（剩下的都是正确行）
              若仍有错误行残留 / 全选行数对不上 → 自动退回逐行勾选（安全）
              → 「批量正确」+确认
   ↓
等下一页数据自动刷新（首行 key 变化）→ 下一轮 …… 直到无新数据/超时自动停
```

> **10.1.1 的防「自动暂停」机制**：① 列表空了不直接结束 → 点页面「查 询」刷新确认，**连续 2 次仍无数据（出现「暂无数据」空态）才算清完**；② 本轮异常（含严格等待超时）→ 默认**重试 2 次**后才停；③ 最大页数 50 → **999**；④ 标签页在后台会提示（浏览器节流会让脚本变慢）。
> **上报字段（10.1.1）**：`数据id(第2列)`、`key_id(第15列)`、antd 行 key 三个都记（第2列为空时额外带整行文本）；开跑时面板会打印「列自检」前 3 行的第2/7/8/15列，便于核对取列是否正确。

### 三种运行模式

| 模式 | 操作 | 行为 |
|---|---|---|
| 只扫当前页 | 点「只扫当前页」 | 只检测+报告，不勾选、不提交 |
| 测试模式 | 勾选面板「测试模式」后点「开始处理」 | **自动勾选错误行**，但不点任何批量按钮 |
| 正式模式 | 默认（点「开始处理」会弹确认框） | 勾错误 → 批量错误 → 勾正确 → 批量正确 → 等下一页 |

### 面板可调参数

| 参数 | 默认 | 说明 |
|---|:---:|---|
| 低分判错 | ≤74 | 该分及以下直接判错（不送检测） |
| 相似度阈值 | 0.40 | 第5列 vs 第6列，低于则判错（实测同图变体 ≥0.83、异图 ≤0.33） |
| 手机/屏幕阈值 | 0.55 | 调高可减少"疑似手机屏幕"误判 |
| 人物阈值 | 0.35 | 调低更容易认出小人物/远景人物（只作用于 YOLO，人脸命中仍算有人） |
| 每批张数 | 6 | 送检批量（后端限速；合并接口下每行占 1~2 个名额） |
| 上报判定日志 | 开 | 每行判定 POST 到 `/judge_log`（id 取**第2列**），查看 `127.0.0.1:5002/judge_log/view`；后端没开不影响审核 |

另外提供「复制明细(TSV)」「复制判错原因」，便于把逐行判定结果（含相似度、置信度）导出分析。

> 其余可调项（脚本顶部 `CONFIG`）：`emptyConfirmTimes`(空列表确认次数，默认2)、`maxProblemRetries`(异常重试次数，默认2)、`problemRetryDelayMs`(重试前等待，默认5s)、`maxRounds`(最大页数，默认999)、`useReviewApi`(是否用合并接口)。

## 三、其他脚本

### 短剧审核-标签版 v2.2-YOLO（提取 + 删除）

单浮窗、顶部标签切换：

| 标签 | 功能 |
|---|---|
| 人脸识别提取（默认先显示） | 遍历所有页，提取"无人脸 或 名称含内置17个关键词 或 分数低于阈值"的 key_id，完成后自动复制到剪贴板 |
| 批量判错删除 | 全选当前页 → 批量错误 → 确认 → 等下一批 → 循环直到删完（20 秒无新数据自动停止） |

> 关键词内置在脚本里（与《短剧关键词.txt》同源），面板输入框留空即使用内置词表，填写则覆盖。

### 低分key_id采集 / 无人脸ID提取 / 自动全选批量删除

- **低分key_id采集**：遍历所有页，采集"得分 ≤ 阈值 或 第7列名称含关键词"的 key_id（翻页用"页码高亮 + 首行 key_id 变化"双保险判定，修复翻页过快导致数据不全）；
- **无人脸ID提取**：批量下载图片 → `/detect_batch` 人脸检测，提取"无人脸 / 含关键词 / 低分"的 key_id；
- **自动全选批量删除**：全选 → 批量删除 → 确认 → 循环，5.0 版起加入"判错确认 + 严重等待"能力（见历史版本）。

## 四、后端依赖

标记 ✅ 的脚本需要 [../backend](../backend/) 提供的本地服务：

| 接口 | 用途 |
|---|---|
| `POST /review_batch` | **合并接口（10.1）**：一次请求同时做「第5列vs第6列 相似度」+「第5列图 人物/手机/屏幕检测」；相似度不过阈值直接返回、跳过检测 |
| `POST /detect_batch_detail` | 人物 / 人脸 / 手机 / 屏幕检测（带置信度，阈值可由脚本传入） |
| `POST /detect_batch` | 批量人像检测（兼容旧脚本） |
| `POST /compare` | 第5列 vs 第6列 图片相似度 |
| `POST /detect` | 屏幕坐标截屏 + 检测（预览大图方案） |
| `POST /health` | 健康检查（脚本启动时自检） |

接口契约与算法见 [../docs/后端接口与算法说明.md](../docs/后端接口与算法说明.md)；模型文件准备见 [../backend/README.md](../backend/README.md)。

## 六、注意事项

- 「批量错误 / 批量正确 / 批量删除」都是**不可逆操作**，建议先用「只扫当前页」或「测试模式」核对判定结果；
- 依赖屏幕截图的功能需要浏览器窗口不最小化、不被遮挡，缩放建议 100%；
- 若出现大量"缺图/检测失败"：脚本已做图片预热（滚动触发懒加载），仍多时可检查网络，或把 `onDownloadFail` 改为 `skip`（脚本顶部 `CONFIG`）。
