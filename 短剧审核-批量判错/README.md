# 短剧审核 — 智能判错系列（`dramaReview*`）

目标页面：`https://tools.vobile.cn/quality/dramaReview*`（Vobile 短剧审核页，Ant Design Pro Table）

> ⭐ **当前唯一推荐：`短剧审核9.1.user.js`（相似度矩阵版，内部版本 9.1.8）**。历史版本全部保留在 `历史版本/`，仅作回溯与对照调试用。
>
> 📌 **一句话机制**：除少数「硬规则」外，**一切都展开核对**（v9.1.7 起）——
> **展开后满足任一即通过**：子样本得分 **> 95 的条数 ≥ 4**（大量高分数据）或 **777 / 601 达到门槛**（前人已判定）；**码门槛按合集大小分档**（v9.1.8）：子样本 **≤ 30 条的小合集只要 ≥ 2 条**，> 30 条的大合集要求 **≥ 4 条**；都不满足 → 全错。
> **仍然直接全错的只有这些硬规则**：多字终极关键词命中 / 单字终极关键词（第4列也没有该字）/ 普通关键词仅在第3列 / **匹配分 < 低分下限 90（面板可调）**。
> **相似度与匹配分不再决定「通过与否」**，仍会写进判定日志与判定理由，便于事后分析（「不相似≤95 直接全错」「匹配分读不到直接全错」这两条已在 9.1.7 取消）。
> 全错流程收尾：全选 + 批量错误（等全部 594）后**点页面「查 询」刷新列表**（不再点「全剧审核」，全错数据会自己移走）。终极关键词 / 关键词双列比对仍最优先。
> **单字终极关键词走双列比对**（v9.1.6 修复）：多字终极关键词（红果/动画/免费/剪辑…）命中即直接全错；单字（当前只有「画」）则要求**第4列也没有该字**才全错 —— 否则像「画币为诺…」这种正常剧名会被误杀。
> **判定日志上报**（v9.1.5）：面板可勾选「上报判定日志」，每条判定 POST 到 `http://127.0.0.1:5002/judge_log`，记录的 id 用【子样本第一条 id】（子样本第2列），查看地址 <http://127.0.0.1:5002/judge_log/view>（可筛选/导出 CSV）。后端没开只提示一次并冷却 60s，不影响审核。
>
> 🔍 完整机制拆解（判定优先级、展开核对判据、等待/重试/跳过、面板与日志字段、已发现的疑点）：见 **[../docs/短剧审核9.1判定机制详解.md](../docs/短剧审核9.1判定机制详解.md)**。
>

## 一、9.1 判定链（当前实现，v9.1.8）

每个合集（母行）按以下**优先级**判定；前一条命中即不再执行后面的判定：

```
⓪  多字终极关键词：第3列（短剧名）命中 ultimateKeywords 中任意「≥2 字」的词
      红果 / 充电专属 / 动画 / 免费 / 剪辑 / 花絮 / 拍摄 / 论剑大会 / 动漫 / 定档 / 首播
      → 模式2（全错），不执行任何后续判定

⓪-2 单字终极关键词：第3列命中「画」且【第4列也没有这个字】
      → 模式2（全错）；若第4列也有「画」→ 不算命中，继续往下判定

①  普通关键词双列比对：第3列命中 nameKeywords（25 个）中的第一个词
      ├─ 第4列（疑似抄袭原短剧名）也有【同一个词】 → 疑似正确，继续往下判定
      └─ 第4列没有该词                             → 模式2（全错）

②  低分保护：匹配分(第5列)可读 且 < lowScoreFloor（默认 90，面板可调，0=关闭）
      → 模式2（全错）—— 这是 9.1.7 之后【唯一】不看子样本的硬规则

③  其余一切情况 → 【展开核对】（统一判据，见下）：
      得分(子样本第8列) > 95 的条数 ≥ 4                  → 模式1（通过：点「全剧审核」）
      或 状态码 777 / 601 各自达到门槛（小合集 ≥2、大合集 ≥4）→ 模式1
      两者都不满足                                        → 模式2（全错）
```

> **相似度在这里的作用**：第3列 vs 第4列「连续 2 字相同 或 公共不同字 ≥3」判为相似，
> 9.1.7 之后**只写进日志与判定理由**（`expandKind`：`similar-high` / `similar` / `dissimilar-high` / `dissimilar` / `no-score`），**不再决定通过与否**。
> 同理，面板上的「匹配分阈值」（`parentScoreThreshold`=95）现在**只影响日志标签**，不影响结果。

### 展开核对的分档细节（v9.1.8）

| 子样本条数（展开后渲染出的行数） | 777 / 601 门槛 | 高分判据（第8列 > 95 的条数） |
|---|:---:|:---:|
| **≤ 30 条**（`smallCollectionMaxRows`，小合集） | 每个码 **≥ 2** 条（`correctCodeMinCountSmall`） | **≥ 4** 条（`highScoreMinCount`，不分档） |
| **> 30 条**（大合集） | 每个码 **≥ 4** 条（`correctCodeMinCount`） | **≥ 4** 条 |

- 777 与 601 **各自独立计数**，任一个达标即可通过；
- 高分判据**不分合集大小**，统一「>95 的条数 ≥ 4」；
- 小合集判定用的是**展开后实际渲染出的子样本行数**（若子表分页，见第九节注意事项）。

### 两种模式的后续动作

| 模式 | 含义 | 执行动作 |
|---|---|---|
| **模式1** | 判该合集正确 | 展开合集 → 点「全剧审核」+ 确认 → 等转圈结束 → 等合集被移走（行消失 / 该行变「已审核」/ 第2列 id 变化） |
| **模式2** | 判该合集全错 | 展开合集 → **全选全部子样本**（表头全选框优先，逐行兜底）→ 「批量错误」+ 确认 → **等全部子样本状态码 = 594 且转圈结束** → 落库缓冲 1s(慢合集 3s) → 点页面「查 询」刷新列表 → 等该合集移走 |

> 模式2 即使当前子样本里已经没有 `0`（例如全是 777/601），也**必须**执行「全选 + 批量错误」，不存在跳过判错的路径。

## 二、稳定性机制

| 机制 | 说明 |
|---|---|
| **严格等待加载** | 点击任何按钮前 / 展开后 / 勾选前后 / 提交后，都必须等 antd 转圈（`.ant-spin-spinning`、`.ant-spin-dot-spin`、`button.ant-btn-loading`）消失，且**连续 800ms 无转圈**才算加载完成；转圈期间不做完成判定。可在面板关闭 |
| **判错完成确认** | 「批量错误」后要求**全部子样本 = 594** 且**无转圈**才算完成，避免系统还在处理就点「查询」 |
| **合集移走判定** | 只用**第2列合集 id**（唯一标识）判断合集是否已移走，不用文本（避免文本重复导致卡死） |
| **等待期重试** | 等待的第 30s / 60s 各重试点击一次同一按钮（含首次每个按钮最多 3 次）；**仅当页面已静止（无转圈）但状态没变化**时才重试 |
| **永久跳过** | 重试后仍无响应/异常 → 收起该合集并**永久跳过**，换下一行继续（不整脚本停止）；「复制跳过清单」导出 id/名称/原因（TSV） |
| **匹配分读不到保护** | 页面上**真正相邻**的 N 行（默认 3）读不到第5列匹配分 → 立即停止运行并弹窗提示（疑似页面改版/选择器失效），避免整批合集被误判。中间夹着已审核/已跳过的行会打断计数；面板「异常行上限」可调，0=关闭 |
| **慢处理** | 集数（第10列）> 300 的合集使用更长的等待上限（展开 30s / 等待 150s）。面板「慢处理集数」可调 |
| **按钮定位防误点** | 按钮查找严格限定「本行 → 本行展开区 → 几何上属于本行的按钮」，不会误点其它合集的按钮 |
| **防重复提交 / 防重复处理** | 提交按钮消失即视为已提交；`doneIds` 记录本轮已处理过的合集 id，避免「查 询」刷新后列表里同一合集被重复处理 |

面板能力：可拖拽、可最小化，实时状态栏（当前步骤 / 合集名 / 594 进度 / 等待原因）、统计「已完成 / 已跳过 / 模式1 / 模式2」、逐行判定日志（保留最近 200 行）、「复制跳过清单」；启动时自动打印页面结构自检。

## 三、配置参数（脚本顶部 `CONFIG`）

| 参数 | 默认 | 说明 |
|---|:---:|---|
| `parentScoreThreshold` | 95 | 【面板可调·**9.1.7 起仅影响日志标签**】匹配分 > 该值 → 日志里标 `*-high`，不再影响通过与否 |
| `highScoreThreshold` / `highScoreMinCount` | 95 / 4 | 展开核对的高分判据：子样本第8列 **> 95 的条数 ≥ 4** → 模式1 |
| `judgeCodes` | `['777','601']` | 参与计数的子样本状态码（各自独立计数） |
| `correctCodeMinCount` | 4 | **大合集**（子样本 > 30 条）任一码条数 ≥ 该值 → 模式1 |
| `correctCodeMinCountSmall` | 2 | **小合集**（子样本 ≤ 30 条）任一码条数 ≥ 该值 → 模式1 |
| `smallCollectionMaxRows` | 30 | 小合集判定边界（子样本条数 ≤ 该值） |
| `lowScoreFloor` | 90 | 【面板可调·0=关闭】匹配分 < 该值 → 一律模式2（唯一不看子样本的硬规则） |
| `noScoreStopCount` | 3 | 【面板可调·0=关闭】相邻 N 行读不到匹配分 → 立即停止 |
| `queryBtnText` | `'查询'` | 模式2 收尾点这个按钮刷新列表 |
| `wrongCode` / `unjudgedCode` | 594 / 0 | 判错完成码 / 未判定码 |
| `ultimateKeywords` | 12 个 | 终极关键词：多字命中即全错；单字（「画」）需第4列也没有该字 |
| `nameKeywords` | 25 个 | 普通关键词（双列比对：仅第3列命中 → 全错） |
| `similarMinSubstr` / `similarMinCommonChars` | 2 / 3 | 相似判定：连续 2 字相同 或 公共不同字 ≥3（9.1.7 起只入日志） |
| `slowEpisodeThreshold` | 300 | 【面板可调】集数 > 该值 → 慢处理（更长等待） |
| `strictLoading` | true | 【面板可调】严格等待加载（转圈闸门） |
| `loadingWaitMax` / `loadingWaitMaxSlow` | 90s / 150s | 单次等待「加载完成」上限；`loadingCalmMs`=800 |
| `expandWaitMax` / `Slow` | 15s / 30s | 展开合集后等子样本出现的上限 |
| `batchErrorWaitMax` / `Slow` | 90s / 150s | 批量错误后等全部 594 的上限（需 > 60s 以容纳 30s/60s 重试） |
| `fullReviewWaitMax` / `Slow` | 90s / 150s | 等待合集移走的上限 |
| `settleAfterBatchError` / `Slow` | 1s / 3s | 判错成功后的落库缓冲 |
| `retryEnabled` / `retryAtSec` | true / [30,60] | 等待期重试开关与时间点（每按钮最多 3 次） |
| `modalWaitMax` / `batchBtnWaitMax` / `checkInterval` | 8s / 5s / 500ms | 确认弹窗等待 / 按钮禁用等待 / 轮询间隔 |
| `reportEnabled` | true | 【面板可调】上报判定日志到 `backendBase` + `/judge_log` |
| `backendBase` / `reportTimeoutMs` / `reportRetryCooldownMs` | `http://127.0.0.1:5002` / 8s / 60s | 后端地址 / 上报超时 / 失败冷却 |
| `startRow` | 1 | 【面板可调】起始行号 |
| `afterProblemDelay` / `maxSkipCount` | 2s / 20 | 跳过合集后等待 / 最多跳过多少个合集（超过则停止提示人工） |

## 四、页面结构依赖

```
母行   tr.ant-table-row.ant-table-row-level-0
  ├── 第2列  合集 id（唯一，用于判断合集是否已移走）
  ├── 第3列  短剧名        ← 终极关键词 / 普通关键词 / 相似度比对
  ├── 第4列  疑似抄袭原短剧名 ← 关键词双列比对 / 相似度比对 / 单字终极关键词比对
  ├── 第5列  匹配最高分     ← 低分保护 + 日志标签（可读性由「相邻读不到」保护监控）
  ├── 第7列  审核状态（含"已审核" → 跳过该行）
  ├── 第10列 集数           ← 慢处理判定
  └── 展开图标 .ant-table-row-expand-icon
展开行 tr.ant-table-expanded-row
  └── 子表格 .ant-pro-table
       ├── 子样本第1列  复选框（表头全选框 + 逐行兜底）
       ├── 子样本第2列  id（上报日志取【第一条】的 id）
       ├── 子样本第3列  状态码（0=未判定 / 594=判错完成 / 777·601=前人已判定，参与计数）
       ├── 子样本第8列  得分（> 95 的条数用于展开核对）
       └── 工具栏「批量错误」按钮
母行按钮：「全剧审核」；页面级按钮：「查 询」
```

若页面改版导致选择器失效：启动时控制台会打印前两行的解析结果（id / 短剧名 / 原短剧名 / 匹配分 / 集数 / 状态）与相似判定，据此调整脚本顶部 `SELECTORS`。

## 五、使用流程

1. Tampermonkey 安装 `短剧审核9.1.user.js`（**停用其它同页面脚本**）；
2. 打开短剧审核页，右下角出现紫色「短剧审核助手 9.1」面板；
3. 按需调整：起始行号 / 匹配分阈值（仅日志标签）/ **低分下限** / **异常行上限** / 慢处理集数，是否启用「严格等待加载完成」与「上报判定日志」；
4. 点「开始运行」→ 全自动循环：逐行判定 → 模式1 点「全剧审核」／模式2 全选 + 批量错误 + 「查 询」刷新 → 直至无待处理合集（弹窗汇总处理数与跳过清单）；
5. 随时可「停止」；需要排查时用「复制跳过清单」；想看历史判定打开 <http://127.0.0.1:5002/judge_log/view>（需后端已启动）。

## 七、注意事项

- 脚本会真实执行「批量错误」「全剧审核」，属**不可逆业务操作**，请先在少量数据上验证关键词与阈值；
- 同一页面请勿同时启用多个短剧审核脚本；
- 合集名命中关键词的规则**极易命中**（含"剧""动""画"等单字），如发现大量合集被判全错，请收紧 `nameKeywords` / `ultimateKeywords`；
- 9.1.7 之后「通过与否」只由**子样本质量**（高分条数 / 777·601 条数）决定，相似度与匹配分**不再参与决策**，仅作日志留痕 —— 想调整松紧只改 `highScoreThreshold` / `highScoreMinCount` / `correctCodeMinCount` / `correctCodeMinCountSmall` / `smallCollectionMaxRows` / `lowScoreFloor`。
