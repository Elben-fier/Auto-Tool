# 短剧审核 — 智能判错系列（`dramaReview*`）

目标页面：`https://tools.vobile.cn/quality/dramaReview*`（Vobile 短剧审核页，Ant Design Pro Table）

> ⭐ **当前推荐：`短剧审核9.0.user.js`**。历史版本全部保留在 `历史版本/`，仅作回溯与对照调试用。

---

## 一、9.0 判定链（当前实现）

每个合集（母行）按以下优先级判定，得出结论后自动执行对应动作：

```
⓪ 终极关键词：第3列（短剧名）命中 12 个终极关键词之一
     红果 / 充电专属 / 动画 / 免费 / 剪辑 / 花絮 / 拍摄 / 论剑大会 / 动漫 / 定档 / 首播 / 画
     → 【模式2】全选 + 批量错误 + 全剧审核（不执行任何后续判定）

① 普通关键词双列比对：第3列命中关键词
     ├─ 第4列（疑似抄袭原短剧名）也有【同一个词】 → 疑似正确，继续后续判定
     └─ 第4列没有该词                              → 【模式2】

② 相似度闸门（仅当短剧名 ≤4 字时执行；与第4列比对"连续2字相同 或 公共不同字≥3"）
     ├─ 相似 → 疑似正确，继续后续判定
     └─ 不相似：匹配分 < 90  → 【模式2】
                匹配分 ≥ 90（或读不到）→ 按 ④ 的机制展开判定

③ 匹配分 > 95           → 【模式1】不展开合集，直接点「全剧审核」

④ 匹配分 ∈ [90, 95]     → 展开合集后判断：
     子样本得分(第8列) ≥90 的条数 ≥3  或  存在状态码 601/777
     ├─ 满足 → 【模式1】全剧审核（不勾选）
     └─ 不满足 → 【模式2】全选 + 批量错误 + 全剧审核

⑤ 匹配分 < 90           → 【模式2】（不展开）

⑥ 匹配分读不到          → 展开看 601/777 痕迹：有 → 模式1；无 → 模式2
```

**两种执行动作**

| 模式 | 动作 |
|---|---|
| 模式1 | 直接点「全剧审核」+ 确认（不勾选、不判错） |
| 模式2 | 全选子样本 → 「批量错误」+ 确认 → **等全部子样本状态码变 594 且转圈结束** → 落库缓冲 → 「全剧审核」+ 确认 |

## 二、稳定性机制（9.0）

| 机制 | 说明 |
|---|---|
| **严格等待加载** | 每次点击按钮前 / 展开合集后 / 勾选前后 / 提交后，都必须等 antd 转圈（`.ant-spin-spinning`、`.ant-spin-dot-spin`、`button.ant-btn-loading`）消失；转圈期间不做完成判定。可在面板关闭 |
| **判错完成确认** | 批量错误后要求"全部子样本 = 594"**且**"无转圈"，避免系统还在处理就点全剧审核 |
| **合集移走判定** | 全剧审核是否完成**只用第2列合集 id**（唯一标识）判断，不再用文本（避免文本重复导致卡死） |
| **等待期重试** | 第 30s / 60s 各重试点击一次同一按钮（含首次最多 3 次）；仅当"页面已静止但状态没变化"时才重试 |
| **永久跳过** | 重试后仍无响应 → 收起该合集并**永久跳过**，换下一行继续审核（不再整脚本停止）；「复制跳过清单」可导出 id/名称/原因 |
| **慢处理** | 集数（第10列）> 300 的合集使用更长的等待上限（展开 30s / 等待 150s 等） |
| **按钮定位防误点** | 按钮查找严格限定「本行 → 本行展开区 → 几何上属于本行的按钮」，不会误点其它合集的全剧审核 |
| **防重复提交** | 提交按钮消失即视为已提交，不重复点击 |

面板能力：可拖拽、可最小化，实时状态栏（展开 / 判定模式 / 594 进度 / 等待原因），统计「已完成 / 已跳过 / 模式1 / 模式2」，启动时自动打印页面结构自检。

## 三、配置参数（脚本顶部 `CONFIG`，面板可调部分已标注）

| 参数 | 默认 | 说明 |
|---|:---:|---|
| `parentScoreThreshold` | 95 | 母本匹配最高分阈值（> 该值 → 模式1）【面板可调】 |
| `midScoreMin` | 90 | 中间档下限（[90,95] → 展开看子样本） |
| `childScoreGood` / `childScoreGoodMinCount` | 90 / 3 | 子样本"好样本"分数线与最少条数 |
| `correctCodes` | `['777','601']` | 子样本状态码中代表"前人已判定/有正确数据"的码 |
| `wrongCode` / `unjudgedCode` | 594 / 0 | 判错完成码 / 未判定码 |
| `ultimateKeywords` | 12 个 | 终极关键词（第3列命中即全错） |
| `nameKeywords` | 25 个 | 普通关键词（双列比对用） |
| `similarGateNameLen` | 4 | 短剧名 ≤ 该长度才走相似度闸门 |
| `similarMinSubstr` / `similarMinCommonChars` | 2 / 3 | 相似判定阈值（连续2字 / 公共字3个） |
| `slowEpisodeThreshold` | 300 | 超过该集数视为"慢合集" |
| `strictLoading` | true | 严格等待加载（转圈闸门）【面板可调】 |
| `loadingWaitMax` / `Slow` | 90s / 150s | 单次等待加载完成的上限 |
| `retryEnabled` / `retryAtSec` | true / [30,60] | 等待期重试开关与时间点 |
| `startRow` | 1 | 起始行号【面板可调】 |
| `maxSkipCount` | 20 | 最多跳过多少个合集（超过则停止提示人工） |

## 四、页面结构依赖

```
母行   tr.ant-table-row.ant-table-row-level-0
  ├── 第2列  合集 id（唯一，用于判断全剧审核是否完成）
  ├── 第3列  短剧名        ← 终极关键词 / 普通关键词 / 相似度比对
  ├── 第4列  疑似抄袭原短剧名 ← 关键词双列比对 / 相似度比对
  ├── 第5列  匹配最高分     ← 分档判定
  ├── 第7列  审核状态（"已审核" 视为已完成）
  ├── 第10列 集数           ← 慢处理判定
  └── 展开图标 .ant-table-row-expand-icon
展开行 tr.ant-table-expanded-row
  └── 子表格 .ant-pro-table
       ├── 子样本第1列  复选框
       ├── 子样本第3列  状态码（0 / 594 / 601 / 777）
       ├── 子样本第8列  得分
       └── 工具栏「批量错误」按钮
母行按钮：「全剧审核」
```

若页面改版导致选择器失效：启动自检会在控制台打印前两行的解析结果（id / 短剧名 / 原短剧名 / 匹配分 / 集数 / 状态），据此调整脚本顶部 `SELECTORS`。

## 五、使用流程

1. Tampermonkey 安装 `短剧审核9.0.user.js`（**停用其它同页面脚本**）；
2. 打开短剧审核页，右下角出现紫色「短剧审核助手 9.0」面板；
3. 按需调整：起始行号 / 匹配分阈值 / 慢处理集数，是否启用「严格等待加载完成」；
4. 点「开始运行」→ 全自动循环处理，直至无待处理合集（弹窗汇总处理数与跳过清单）；
5. 随时可「停止」；需要排查时用「复制跳过清单」。

## 七、注意事项

- 脚本会真实执行「批量错误」「全剧审核」，属**不可逆业务操作**，请先在少量数据上验证关键词与阈值；
- 同一页面请勿同时启用多个短剧审核脚本；
- 合集名命中关键词的规则**极易命中**（含"剧""动""画"等单字），如发现大量合集被判全错，请收紧 `nameKeywords` / `ultimateKeywords`。
