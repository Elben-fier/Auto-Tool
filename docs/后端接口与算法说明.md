# 后端接口与算法说明

服务地址：`http://127.0.0.1:5002`（仅本机回环，无对外暴露）
代码位置：`backend/`（`server.py` 路由，`detector.py` 算法）

---

## 一、接口清单

### 1. `/health`（GET / POST）

健康检查。

```json
{"status": "ok"}
```

### 2. `/detect`（POST）

**按屏幕绝对坐标截屏再做检测**（给"预览大图截屏"类脚本用）。

请求：

```json
{"left": 100, "top": 200, "width": 300, "height": 400}
```

响应：

```json
{"hasFace": true}
```

`hasFace` 语义 = **画面含真人相关内容**（人物/人脸/背影/侧脸）。截到的区域为空或宽度/高度 ≤ 0 时直接返回 `false`。

### 3. `/detect_batch`（POST）

批量人像检测，**兼容早期脚本**（返回布尔数组）。

请求：

```json
{"images": ["<base64>", "<base64>"]}
```

响应：

```json
{"results": [true, false]}
```

### 4. `/detect_batch_detail`（POST）

批量**明细**检测（当前推荐脚本使用）。阈值可由前端传入，便于在面板上现场调参。

请求：

```json
{
  "images": ["<base64>", "<base64>"],
  "person_conf": 0.35,
  "object_conf": 0.55
}
```

响应：

```json
{
  "results": [
    {
      "person": true,
      "face": false,
      "phone": false,
      "screen": false,
      "ok": true,
      "conf": {"person": 0.89, "phone": 0.0, "screen": 0.0}
    }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `person` | 有人物：YOLO person 命中（≥ `person_conf`）**或** YuNet 人脸命中（阈值固定 `FACE_CONF=0.55`） |
| `face` | 仅由人脸模型命中的情况（YOLO 没出 person 框） |
| `phone` | 检出手机（COCO `cell phone`=67，置信度 ≥ `object_conf`） |
| `screen` | 检出屏幕（COCO `tv`=62、`laptop`=63，置信度 ≥ `object_conf`） |
| `ok` | **合格画面** = `person && !phone && !screen` |
| `conf` | 三类原始置信度（0~1），便于标定阈值与排查 |

> 阈值说明：`person_conf` / `object_conf` 不传则用后端默认值。**手机/屏幕的后端默认阈值故意设得较松（0.25）**，只做"候选上报"，真正判定阈值由前端传入（脚本面板默认 0.55，避免"画面里有一点像手机屏幕"就被误判）。

### 5. `/compare`（POST）

两两图片相似度（用于"第5列图 vs 第6列图"一致性校验）。

请求：

```json
{"pairs": [{"a": "<base64>", "b": "<base64>"}]}
```

响应：

```json
{"results": [{"ok": true, "sim": 0.83, "ssim": 0.75, "hash8": 0.92, "hash16": 0.88, "hist": 1.0, "aspect": 0.99}]}
```

`ok=false` 表示图片缺失或解码失败（前端按自己的策略处理：跳过 / 判错）。

### 6. `/debug_screenshot`（POST）

调试用：按坐标截屏保存到 `backend/debug_screenshot_<时间戳>.png`，返回文件路径与尺寸。

## 二、算法说明

### 1. 人像判定（`FaceDetector.detect_detail`）

```
YOLOv8n(ONNX, 640×640 letterbox, COCO 80类)
   ├─ person 类置信度 ≥ PERSON_CONF      → 有人物
   └─ 否则 YuNet 人脸检测（含水平翻转兜底）→ 命中则也算有人物
手机/屏幕：cell phone(67) / tv(62) / laptop(63) 置信度 ≥ OBJECT_CONF
```

- **为什么要两级**：YOLO person 对"全身/背影/侧身/大半身"稳；但**纯脸部特写**可能不出 person 框，用 YuNet 兜底；
- **水平翻转兜底**：YuNet 对侧脸/偏脸漏检时，把图水平镜像再检一次，提升侧脸检出率；
- **无 onnx 时自动降级**：只有 HOG 行人检测（OpenCV 内置），无手机/屏幕识别能力。

### 2. 图片相似度（`image_similarity`）

加权组合，输出 0~1（越大越像）：

```
sim = 0.50 × SSIM       （结构相似度，对内容差异最灵敏）
    + 0.25 × dHash16    （16×16 差值哈希一致率）
    + 0.15 × dHash8     （8×8 差值哈希一致率）
    + 0.05 × HSV 直方图相关性（H-S 二维，32×32）
    + 0.05 × 宽高比一致性
```

**实测分离度**（用于选阈值）：

| 场景 | 相似度 |
|---|---|
| 同一张图自身 / 缩放一半 / 轻度模糊 | 1.000 |
| 同图 + JPEG 质量 30 | 0.999 |
| 同图 + 亮度 +40 | 0.889 |
| 同图 + 裁剪平移 | 0.833 |
| **完全不同的两张图** | **0.31 ~ 0.33** |
| 同图上半 vs 下半 | 0.315 |

→ 阈值取 **0.40 ~ 0.60** 均可干净区分；脚本默认 **0.40**（偏宽松，减少误杀正确数据）。

> 注意：**水平翻转**的同一张图相似度只有 0.34（会被判为"不相似"）。若业务上镜像图应视为相同，需要在算法里增加翻转比对分支。

### 3. 速率限制（TaskQueue）

- 限制口径是 **图片张数**（不是请求数）：`rate_limit=4.5` → 每张间隔约 0.22s；
- `/detect_batch` 与 `/detect_batch_detail` **逐张** acquire/release，避免"一批 3 张只扣 1 个名额"导致限速失效；
- 队列满（默认 100）时返回 **HTTP 429**，脚本收到 429 会等待 0.6~0.8s 自动重试；
- 服务为**单线程串行**（`threaded=False`），保证 CPU 占用平稳。

---

## 三、性能参考

| 项目 | 实测值（本机 CPU） |
|---|---|
| 单张人像检测 | 0.04 ~ 0.09 s |
| 批量吞吐（含限速） | 约 **4.3 ~ 4.4 张/秒**（`rate_limit=4.5`） |
| 单对图片相似度 | < 0.02 s |
| 常驻内存 | 约 300 ~ 500 MB（onnxruntime + opencv） |

## 四、修订记录

| 版本 | 变更 |
|---|---|
| v1（初版） | Flask + Haar 级联人脸检测 + LAC 文本人名识别，限速 5 条/秒 |
| v2.0 | 人像检测升级为 **YOLOv8n(person) + YuNet(人脸兜底)**，去掉 Haar；限速改 4 条/秒 |
| v2.1 | 新增 `/detect_batch_detail`（手机/屏幕 + 置信度、阈值可由前端传入）；限速按张计数（4.5 张/秒）；**移除 LAC 文本人名识别**（`NameDetector`、`/detect_text_name`、LAC 依赖） |
| v2.2 | 新增 `/compare` 图片相似度接口（SSIM + dHash + 直方图 + 宽高比） |
