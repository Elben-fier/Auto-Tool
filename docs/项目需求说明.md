## 一、项目背景与核心目标

本工具用于短剧内容审核场景，通过**本地屏幕视觉识别 + 文本实体识别**的方式，替代人工完成重复的条目初筛，自动标记符合条件的审核项，提升审核效率。

核心能力：

1. 自动识别审核列表中的图片是否包含人脸，识别到则自动勾选对应条目
2. 自动识别审核列表中的文本是否包含人名，识别到则自动勾选对应条目
3. 适配分页审核流程，翻页后自动重新扫描
4. 严格控制本地资源占用，避免造成电脑过高负载

## 二、业务流程

工具需严格匹配以下审核作业流程：

1. 审核页面为表格形式，单页展示约 100 条待审核数据
2. 工具自动扫描当前页所有条目，对每条的图片/文本执行检测
3. 检测命中（含人脸/含人名）的条目，自动勾选行首复选框
4. 人工确认后点击「批量正确」提交已勾选条目
5. 剩余未勾选条目由人工点击「批量错误」提交
6. 页面刷新加载下一页数据，工具自动重置状态，重新扫描新一页内容

## 三、整体技术架构

采用「本地 Python 后端 + 浏览器油猴脚本」的分离架构：

- **后端**：Python 3.10 环境，运行于 Windows 系统，提供本地 HTTP 接口，负责任务队列调度、屏幕截图、人脸检测、文本人名检测
- **前端**：Tampermonkey 油猴脚本，注入 Edge 浏览器的审核页面，负责 DOM 元素定位、状态管理、事件监听、调用后端接口并执行勾选操作
- **通信**：本地回环 HTTP 接口，地址 `127.0.0.1:5002`，所有数据本地处理，不上传至外部服务器

## 四、Python 后端功能规范

### 1. 人脸检测接口（/detect）

#### 输入参数

接收 POST JSON 请求，字段为图片在浏览器视口内的相对坐标：

| 字段 | 类型 | 说明 |
|------|------|------|
| left | 数值 | 图片左上角相对于浏览器视口左侧的像素距离 |
| top | 数值 | 图片左上角相对于浏览器视口顶部的像素距离 |
| width | 数值 | 图片宽度（像素） |
| height | 数值 | 图片高度（像素） |

#### 处理逻辑

1. 通过 `win32gui` 自动定位标题包含指定关键词的 Edge 浏览器窗口，获取浏览器客户区的屏幕绝对坐标
2. 将视口相对坐标换算为屏幕绝对坐标，使用 `mss` 仅截取图片对应的局部屏幕区域，不截取全屏
3. 使用 OpenCV 内置 Haar 级联检测器（`haarcascade_frontalface_default.xml`）对截图执行人脸检测
4. 适配 Windows 系统高 DPI 缩放，保证坐标映射准确

#### 输出结果

```json
{"hasFace": true}
```

- `hasFace` 为布尔值，检测到至少 1 张人脸返回 `true`，否则返回 `false`
- 队列已满时返回状态码 429

### 2. 文本人名检测接口（/detect_text_name）

#### 输入参数

接收 POST JSON 请求：

| 字段 | 类型 | 说明 |
|------|------|------|
| text | 字符串 | 待检测的中文文本 |

#### 处理逻辑

使用百度 LAC 中文实体识别模型，对文本执行命名实体识别，匹配标签为 `PER` 的人物实体。

#### 输出结果

```json
{"hasPerson": true}
```

- `hasPerson` 为布尔值，检测到至少 1 个人名返回 `true`，否则返回 `false`

### 3. 性能与资源控制

1. 采用单线程任务队列，所有检测任务串行执行，禁止并发处理，避免 CPU 占用过高
2. 检测限速：每秒最多处理 3 条检测请求
3. 截图数据直接在内存中处理，不写入本地磁盘，无磁盘 IO 开销
4. 正常运行时 CPU 占用控制在 15%–30% 区间，无内存累积泄漏

## 五、油猴前端脚本规范

### 1. 页面适配规则

目标页面为 Ant Design 组件库的表格页面，固定 DOM 选择器如下：

| 元素 | 选择器 | 说明 |
|------|--------|------|
| 表格行 | `tr.ant-table-row.ant-table-row-level-0` | 单条审核数据的行容器 |
| 行唯一标识 | `data-row-key` 属性 | 用于标记已处理条目，避免重复检测 |
| 复选框 | `.ant-checkbox-wrapper` | 点击该元素触发行勾选，兼容 AntD 组件交互逻辑 |
| 审核图片 | `.ant-image-img` | 待检测人脸的图片元素 |
| 表格主体 | `.ant-table-tbody` | 监听该区域 DOM 变化判断翻页 |

### 2. 核心业务逻辑

1. **已处理标记**：使用 Set 集合存储已处理行的 `data-row-key`，同一条目仅检测一次，处理完成后永久跳过
2. **翻页监听**：通过 `MutationObserver` 监听表格主体的子节点变化，检测到表格内容刷新（翻页）时，自动清空已处理集合，触发新一轮全量扫描
3. **滚动防抖**：页面滚动事件添加 300ms 防抖，滚动过程中不触发检测，滚动停止后再执行扫描，避免无效请求
4. **串行处理**：逐行依次调用后端接口，不批量并发发起请求
5. **加载等待**：检测前等待图片加载完成，避免截到空白或加载中的画面

### 3. 日志与交互

1. 在浏览器控制台输出处理日志，包含每行检测结果、当前页扫描完成提示
2. 仅执行勾选操作，不修改页面原有样式、不添加额外 UI 元素、不干扰页面原有功能

## 六、配置参数汇总

| 参数项 | 取值 | 说明 |
|--------|------|------|
| 运行系统 | Windows | 后端运行环境 |
| 目标浏览器 | Microsoft Edge | 脚本运行环境 |
| Python 版本 | 3.10 | 后端运行版本 |
| 滚动防抖时长 | 300ms | 滚动停止后等待扫描的时间 |
| 检测限速 | 3 条/秒 | 单秒最大处理条目数 |
| 人脸检测模型 | OpenCV Haar 正脸检测器 | 优先保证速度 |
| 人名识别模型 | 百度 LAC 本地模型 | 离线运行，识别真实中文人名 |
| 后端服务端口 | 5002 | 本地 HTTP 服务端口 |

## 七、约束与注意事项

1. **窗口约束**：浏览器窗口不可最小化，待检测图片区域不可被其他窗口遮挡，否则截图识别失效
2. **精度建议**：建议浏览器缩放设置为 100%，可保证坐标映射最精准
3. **识别率说明**
   - Haar 人脸检测器对正脸识别效果较好，侧脸、遮挡、模糊图片存在漏检可能
   - LAC 对真实中文人名识别准确，短剧虚构角色名存在漏判可能
   - 可通过调整检测器的 `scaleFactor`、`minNeighbors` 参数平衡误检率与漏检率
4. **数据安全**：所有图片、文本检测均在本地完成，无数据外发，符合审核数据安全要求
